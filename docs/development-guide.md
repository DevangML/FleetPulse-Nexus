# Development Guide — FleetPulse Nexus

Everything needed to run, build, lint, and extend the project.

## 1. Prerequisites

| Tool | Recommended | Notes |
| :--- | :--- | :--- |

## 2. Install

```bash
# Bun (matches the committed lockfile)
bun install

# or npm
npm install
```

## 3. Scripts

| Command | What it does |
| :--- | :--- |
| `bun run dev` / `npm run dev` | Start the Vite dev server with Fast Refresh. |
| `bun run build` / `npm run build` | Type-check (`tsc -b`) **then** produce a production bundle (`vite build`). |
| `bun run preview` / `npm run preview` | Serve the built `dist/` locally. |
| `bun run lint` / `npm run lint` | Run ESLint across the project. |

> The `build` script runs `tsc -b` first, so **type errors fail the build**. Keep the
> tree type-clean.

## 4. Local development flow

```bash
bun install
bun run dev          # open the printed localhost URL
```

The app starts streaming immediately (`isStreaming` defaults to `true`). Use the control
bar to pause/resume, reset counters, and change the ingestion frequency.

## 5. Project conventions

### TypeScript
- Config: `tsconfig.app.json` — `target: ES2023`, `moduleResolution: bundler`,
  `verbatimModuleSyntax: true`, `jsx: react-jsx`.
- Strict lint flags on: `noUnusedLocals`, `noUnusedParameters`,
  `noFallthroughCasesInSwitch`, `erasableSyntaxOnly`.
- `verbatimModuleSyntax` means **type-only imports must use `import type`** (as done in
  `MetricCard.tsx` and `useTelemetryStream.ts`).

### ESLint (flat config, `eslint.config.js`)
- Extends: `@eslint/js` recommended, `typescript-eslint` recommended,
  `eslint-plugin-react-hooks` (flat recommended), `eslint-plugin-react-refresh` (Vite).
- `dist/` is globally ignored.

### Styling
- All app styling lives in `src/index.css` using the CSS `@layer` cascade:
  `reset → theme → base → components → utilities → animations`.
- Prefer existing **design tokens** (`--accent-cyan`, `--bg-glass`, `--glow-red`, …) and
  utility classes (`.card`, `.btn`, `.grid`, `.stack`) over new ad-hoc CSS.

### File organization
- Feature components live under `src/components/<feature>/` (e.g. `telemetry/`).
- Reusable logic → `src/hooks/`.
- Shared types → `src/types/`.
- Global state (future) → `src/store/`.

## 6. Extending the app

### Add a new metric card
1. Add/derive the value in `useTelemetryStream` (extend `TelemetryStats` in
   `src/types/telemetry.ts` if needed).
2. Render a new `<MetricCard>` in `LiveTelemetryStream.tsx` with an appropriate
   `status` threshold.
3. Remember: `MetricCard`'s memo compares `value`, `status`, `title` — make sure your
   value changes are reflected in one of those props.

### Add a new field asset
- Extend the `assets` array in `generatePacket()` inside `useTelemetryStream.ts`.

### Wire the Zustand store
- Implement `src/store/useFleetStore.ts` (currently empty). See the suggested shape in
  [State Management](./state-management.md#5-reserved-zustand-global-store).

## 7. Testing

There is **no test setup** in the repo today (no test runner, no `test` script, no spec
files). Recommended next step: add Vitest + React Testing Library and cover:
- the `useTelemetryStream` reducer math (avg latency, low-battery counting),
- the `MetricCard` memo equality behavior,
- effect cleanup (no interval leaks on unmount / pause).

## 8. Deployment

Static SPA — the `dist/` output from `vite build` can be served by any static host
(Netlify, Vercel, GitHub Pages, S3+CloudFront, nginx). No server runtime or environment
variables are required. There is currently **no CI/CD pipeline, Dockerfile, or `.env`**
in the repository.
